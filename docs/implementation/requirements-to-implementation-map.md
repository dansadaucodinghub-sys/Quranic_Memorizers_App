## Purpose

Give every approved P0 requirement one primary implementation phase, accountable batch/backlog, verification batch/activity, migration scope, control envelope and controlled status.

## Scope

This matrix routes implementation; the full normative wording remains in the frozen P0 requirement sources. Locked architecture applies to every row. Controlled open decisions may refine a row only through change control and must close at their assigned phase gate. No decision blocks QMDB-P1-B01.

## Mapping rules

- Each approved requirement appears exactly once.
- `Primary Batch` is the accountable first destination. Later-phase detail uses the controlled `QMDB-P#-BACKLOG` identifier until decomposed.
- `Verification Batch` names the phase close and preserves the source verification activity.
- `Migration Group` does not authorize schema work before the phase or replace the logical data contract.
- `Security Controls` uses directly cited controls where present; otherwise it records the phase assurance envelope.
- `APPROVED_FROZEN` requires governed change control before alteration.
