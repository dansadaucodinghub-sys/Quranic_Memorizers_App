## Purpose

Map principal queries to bounded consistency-aware paths and give every index a concrete identity, relationship, queue, lookup or tenant-list purpose.

## Scope

The catalog contains 47 principal access patterns and 658 logical indexes. Executable migrations verify DDL with representative `EXPLAIN ANALYZE`, distributions, lock behavior and write cost.

## Index rules

- Equality tenant filters precede state/range/sort columns under MySQL leftmost-prefix behavior.
- Every FK child sequence has a supporting index/compatible prefix; tenant hot paths begin with `workspace_id`.
- Order is equality, selective state, range/time, stable `id`; large lists use keyset pagination.
- Redundant candidates may coalesce only after migration metadata/query evidence; speculative/prefix/JSON indexes are prohibited.
- Queue access uses indexed state/time, primary reads, short `FOR UPDATE SKIP LOCKED`, leases and idempotency.
- Full-text search is a privacy-filtered rebuildable projection, never official authority.
- Selectivity, write amplification, lock range, buffer use and slow-query regressions are release evidence.

## Authoritative concurrency and locking policy

| Operation | Required transaction behavior |
| --- | --- |
| Score Sheet submission | Primary; lock one lineage; compare lock version; validate Assignment/Performance/Ruleset; append version/receipt/audit/outbox atomically. |
| Score reopening | Lock request/current sheet; verify independent approval/version; create replacement; preserve former version. |
| Result finalization/correction | Lock Result/readiness inputs; verify quorum/Appeals/approval; append snapshot/supersession/audit/outbox. |
| Certificate issuance | Lock eligible Result/certificate lineage; unique serial/code; hash/signature reference/outbox atomically. |
| Person merge | Lock candidates in deterministic ID order; verify versions/authority; preserve snapshots; append events. |
| Guardian override | Lock relationship/Consent scope; verify versions/authority; append history. |
| Registration capacity/draw | Lock narrow category/session resource; unique constraints; no broad Edition lock. |
| Queue claiming | Primary indexed state/time with short `FOR UPDATE SKIP LOCKED`; lease, commit, process idempotently. |
| Offline synchronization | Deduplicate; lock central lineage; compare expected version/sequence; accept/reject/hold without overwrite. |

ADR-037 proposes default isolation pending OD-056. Critical transitions use explicit locks, unique keys, optimistic versions, primary reads, deterministic lock order, bounded transactions and governed retry under OD-057. `SKIP LOCKED` is queue-only.

## P3-B02 access-pattern addendum

Private People reads use opaque Person IDs only after exact Account self-link or guardianship authorization. Supporting
indexes cover active Account links, current names, role state, guardian/dependent active pairs and chronology. No
global Person-name search index or public directory query is exposed. Geography selection uses the public B01
State/FCT-to-child lookup and does not prefetch all level-two records.

## P3-B05 identity-resolution access-pattern addendum

Pairing resolution begins with the selector and verifies a versioned HMAC in the Account-bound row; there is no
registry-code, name, birth-date, contact, or public Person lookup path. Account views are indexed by claimant and
status, reviewer queues by bounded status/time keys, and duplicate reports by exact Person/status pairs. Consent and
case-event reads are case-scoped; canonicalization locks the ordered Person pair and bounded participant rows in a
deterministic order. The design deliberately omits name/birth-date discovery indexes and avoids scans that could
enumerate Persons or duplicate candidates.
